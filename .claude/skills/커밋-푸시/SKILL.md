# 커밋-푸시

이 저장소(`my-mannabusiness`) 안에서만 사용한다. 다른 저장소에는 적용하지 않는다.

## 절차

1. **상태 확인**
   - `git status --short`로 미추적 파일과 변경 파일을 확인한다.
   - 변경이 없으면 "커밋할 변경 사항이 없습니다"라고 알리고 끝낸다.
   - 비밀 정보가 의심되는 파일(`.env`, `credentials.json`, `.claude/settings.local.json` 등)은 커밋에서 제외하고 사용자에게 알린다.

2. **대상 브랜치 확인**
   - `git branch --show-current`로 현재 브랜치를 확인한다.
   - 기본 브랜치(main 등)에 있으면 커밋하지 않고 작업 브랜치를 먼저 만들자고 알린다.
   - 세션 지정 브랜치는 `claude/bold-davinci-6y8alr`이다. 다른 브랜치로 푸시하지 않는다.

3. **스테이징**
   - 파일을 이름으로 지정해 `git add <파일>`로 추가한다. `git add -A`는 쓰지 않는다.

4. **커밋**
   - 변경 내용을 보고 `docs:`, `feat:`, `fix:` 등의 접두어와 한 줄 제목을 붙인다.
   - 본문에 무엇을 왜 바꿨는지 한두 줄로 적는다.
   - 마지막 줄에 세션 링크를 넣는다:
     `Claude-Session: https://claude.ai/code/session_01RSH1E8khz2iLdyKDnFg917`
   - 커밋 메시지에 모델 이름이나 모델 식별자를 넣지 않는다.

5. **푸시**
   - `git push -u origin claude/bold-davinci-6y8alr`를 실행한다.
   - 네트워크 오류는 최대 4회까지 점진적으로 재시도한다.
   - 푸시가 거부되면 강제 푸시하지 않는다. `git fetch origin claude/bold-davinci-6y8alr && git merge --no-edit FETCH_HEAD` 후 다시 푸시하고, 사용자에게 알린다.

6. **결과 보고**
   - 커밋 해시, 브랜치, 포함된 파일을 알려준다.
   - 작업 트리가 깨끗한지 `git status --short`로 확인해 보고한다.

## 하지 않는 것

- PR 생성은 사용자가 명시적으로 요청할 때만 한다.
- 강제 푸시, 히스토리 재작성은 하지 않는다.
- 사용자가 요청하지 않은 파일은 커밋에 포함하지 않는다.
